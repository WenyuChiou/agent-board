- **The question files beside progress.md no longer pile up, and an idle poll no longer reads them again (#156).** Every question the pane records leaves small files beside progress.md: a copy of the question as it was, and a proof that an answer or a hide was already used. Nothing ever removed them, and each 2-second poll read every one of them, and the inbox of other agents' turns as well, so a board got slower the longer it was used. Each copy and proof is now read once and remembered by its name, size and time; a file that fails its check is looked at again at every poll, as before; the inbox is read again only when its listing or the list of turns already taken changes. The pane's archive (session start, hourly and the pane's tidy; the board script's `--tidy` does not prune) keeps the newest 16 copies and the newest 16 proofs of each kind, and removes an older one only when the ledger or a newer copy already holds everything it holds, fifty files to a process. A copy that may be the only record of an unresolved question stays, so 16 is a floor, not a limit. That clean-up reads the files again from disk before it removes any, so a copy damaged since the last poll cannot be the newer copy that lets an older one go. The terminal board and the page (`--watch`, `--serve`) remember the files the same way, so a redraw every 2 seconds no longer reads each of them.
  Tests: `an idle poll reads the same few files with piles of captures, proofs and inbox turns waiting`, `an inbox turn that arrives between two polls is read at the next poll`, `a capture is read once, a damaged one is read at every look, and a repaired one is read once more`, `captures and proofs beyond the newest 16 are pruned at tidy, and the ledger still holds every unresolved question`, `twenty unresolved questions with no other copy keep all twenty captures at tidy`, `question captures beyond the newest 16 are pruned once the ledger and a newer copy hold what they hold`, `the newest copy of an open question and the copy the ledger matches exactly are never pruned`, `a capture stays when it may be the only copy of an unresolved question or holds what the ledger lacks`, `an answered question keeps its copies until its retirement proof exists`, `question proofs beyond the newest 16 go only when no ledger record, capture or acknowledgement refers to them`, `pruning reads the files afresh, so a copy damaged on disk since the polls looked is not the newer copy`, `the terminal board reads each question copy and proof once, however often it draws`.
