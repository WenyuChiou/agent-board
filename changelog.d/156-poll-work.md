- **An idle poll is down to a few file checks, and one file read that never answers no longer stops the 2-second poll from redrawing (#156).** The pane still read the questions file and its companions every 2 seconds when nothing had changed. It now reads the questions again only when progress.md, a question file or the folder listing changed by name, size or time, when a file there was written within the last poll, or when the folder does not list. On a test board of 300 blocks, 100 live sessions and 1,000 question records, an idle poll made 17 file operations before this change and makes 5 now; the test holds it to at most 6, the check that #222's journeys left skipped. No file call has a time limit of its own, so one read that never returned (a drive that went away, say) kept the pane from polling again for good. A poll still running after 15 seconds now gives way to a new one at the next 2-second tick, and what its held read of progress.md brings back late is dropped; the questions are waited on for one poll at most, so the line under the prompt and the pane are drawn while a read is held up. While one poll that gave way is still held, no other gives way, so a file that stays held does not gather a read every 15 seconds; the polls run after a write return at once while one is held, as before, so writes do not wait on it. The pane's archive also keeps only the newest three torn questions files (the copies set aside when the file was cut off or garbled), and removes a temporary copy that an interrupted write left once it is a day old and the questions file itself reads; at most 200 of these go in one sweep, the rest at the next.
