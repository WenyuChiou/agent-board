- **OpenCode: the progress tool says why a report was refused, a one-shot run ends its row, and rows are filed under the session's folder (#217).** The tool's steps must be Markdown task lines; a model that sent plain text got only `AGENT_BOARD_REPORT_FAILED`, so it never retried. The tool now describes the step format, and a refused report names the board's reason (`AGENT_BOARD_REPORT_FAILED: INVALID_STEP`), from a board in any language; live, the model then retried and its block was written. OpenCode sends no `session.deleted` for an `opencode run`, so each one left a waiting "Local opencode task" row behind. As OpenCode exits, its plugin now ends the top-level sessions it reported that had finished their reply, all within one 2 s deadline plus the worker's grace, and logs a timeout instead of holding OpenCode's exit; on Windows that took 206 to 587 ms over 10 live runs. A reply that ends just before OpenCode exits counts as ended even while its lookup is still pending. A session still replying is left to go stale by age, and a later report for an ended session reopens its row. A new OpenCode block is filed under the folder the session ran in, not under `## opencode` (other status hooks keep their agent's heading), and an explicit report naming a project moves the session's existing block there.
