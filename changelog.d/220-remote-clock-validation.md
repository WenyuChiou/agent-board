- **Remote reporters / Report clocks** · The Python importer refuses live reports over three days old, including reports without a state, and rejects future UTC seconds before writing anything. Rapid updates and retirement retain their order within the current second; clock refusals use the system language. Old done and ended reports still merge as history (#220).
  Tests: `merge.py refuses a working block whose clock is weeks behind and writes nothing`, `merge.py still merges a done block with an old clock`, `merge.py refuses a future report and validates every fragment before writing the batch`, `the remote live-report age limit accepts exactly three days and rejects the next instant`, `an omitted state uses the waiting age limit and rejects the whole batch without writes`, `rapid reporter updates and retirement merge under the same clock at every part of a second`, `the future guard accepts current-second ordering but refuses the next UTC second`, `remote clock errors are generated from all three string tables and delivered in the CLI language`.
