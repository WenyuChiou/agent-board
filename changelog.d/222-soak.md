- **A long soak of the terminal board and the page server, with its report (#222).** `tests/e2e/soak.mjs` keeps `--watch` and the `--serve` page running side by side on one isolated world for `--minutes` (1 to 45, default 30). `.github/workflows/soak.yml` runs it weekly and on demand, never per pull request. The soak polls the page 500 ms after each answer and grows the data to the scale budget (100 live sessions, 300 blocks, 1,000 question records). It then archives most tasks through the page's own requests and goes on polling. A probe loaded into the board's own processes counts file operations by kind and requests served, and records memory every 10 seconds. The six audit checks are file operations per poll, server memory, question-file pruning, page-server survival, terminal-board survival and memory levelling. Checks that fail on main because of a known problem are marked with their hold id and fail once they pass. They and the run status go to `soak-report.json` and `soak-report.md` after every sample. The world, temp, home and working folders are hidden, and neither the environment nor the page address is written. A bad command line exits 2 with one sentence and creates nothing. The L0 safety scan now also refuses a built-in module loaded through the module loader.
