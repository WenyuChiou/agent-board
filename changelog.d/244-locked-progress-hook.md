- **A hook that finds progress.md locked keeps its event (#244).** Lifecycle hooks retry busy progress-file transactions for about two seconds, then save only the event's metadata in a bounded pending queue and return success. The next transaction on that board replays pending events first, oldest event first, and drops entries that are invalid or older than their session's last report; an entry that a disk or permission error stops is kept and the hook fails. A hook stops replaying before its 3-second limit and queues its own event behind the rest. On Windows, a read-only `progress.md` is not a lock: the hook fails and queues nothing. Explicit reports still fail if the file stays locked. When a read finds `progress.md` locked before anything was written, the board's print, `--keys`, `--watch`, `--chat` and page say only that it is locked by another program and that nothing was changed, without its folder; after a write they still say that files may have changed.
  Tests: `L5 locked file: the hook retries, exits 0, and the Stop event lands on the next run`, `a hook whose progress.md is locked only briefly retries and lands the event at once`, `an explicit report on a locked progress.md still says in one line that it was not saved`, `queued hook events stop at 64 and the next one fails in one plain line`, `a queued event that can no longer apply is dropped without blocking the others`, `L7 errors: every error is one plain sentence with no stack trace and no full path`, `a press that wrote its history before progress.md was locked says files may have changed, not that nothing was`, `a refused rename onto progress.md is a lock on Windows and a failure elsewhere, and any other refusal still fails`, `a queued status event older than its session's last report is dropped instead of moving the session back`, `a read-only progress.md fails in one plain line without queuing the event`, `a queued event with a system error is kept and the hook fails in one plain line`, `hook replay yields at its deadline while an explicit report drains every queued entry`, `queued status events use their start time and reject invalid timestamps`, `a watch view that captured a question before progress.md was locked says files may have changed`.
