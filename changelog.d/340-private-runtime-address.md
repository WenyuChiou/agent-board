- On Windows, the board page keeps its address and token in a dedicated runtime folder with an explicit, non-inherited grant for the current account only. It verifies an existing address file's owner and ACL before reading the token, sets ownership on a new empty file before writing its token, and moves only a verified private legacy address bound to the requested progress file. Current and legacy addresses for another board authorize no request to it. Permission setup fails before the server starts with one bounded line, including in the direct child entry point. The idle period starts after the address is ready, so permission setup does not consume it. Concurrent starts wait within the existing launch deadline for the winning address to finish publishing. Native ACL reads work without PowerShell command discovery (#340).
  Tests: `Windows page address tokens stay in a current-account-only runtime folder`, `runtime ACL validation rejects other owners, other accounts, inherited folders and incomplete grants`, `Windows page ACL setup failure prints one bounded line and writes no token`, `Windows page startup refuses a runtime junction without changing its destination`, `Windows page startup refuses an existing address file granted to another account`, `Windows page startup moves a verified private legacy address once and reuses its page`, `Windows page startup leaves an untrusted legacy address unread and contacts only its new page`, `Windows page startup without XDG runtime keeps the token under the isolated home`, `Windows page ACL checks use the system module instead of an inherited module path`, `Windows page ACL checks work without PowerShell command discovery`, `Windows page token writes explicitly own a new file before trusting its inherited ACL`, `a local board stays available by default while an explicit idle timeout closes only that server`, `a private address renamed from another board is never migrated, contacted or closed`, `Windows concurrent page startup waits for the winning address to finish publishing`.
