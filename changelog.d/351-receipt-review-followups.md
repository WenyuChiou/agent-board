- **A prompt reporter that cannot save its timeout receipt now says so, and a stopped reporter's leftover files are removed (part of #351).** When a timed-out prompt's metadata receipt could not be built or saved, the hook log showed only REPORTER_TIMEOUT, the same as for a saved one; the reporters now log REPORTER_FAILED first. The sh reporter reads every receipt field in one pass instead of starting about 30 processes after its time ran out. Files a stopped reporter leaves in the inbox, including the temporary copy that holds the prompt, are removed after a minute; on PowerShell, one that cannot be removed is logged as CLEANUP_FAILED. A stale temporary file of hook-errors.log is removed by the next hook's log write.
  Tests: `the <name> reporter logs REPORTER_FAILED when its timeout receipt cannot be saved`, `a hook log write sweeps stale hook-errors.log temp files but keeps fresh ones`, `a reporter sweeps scratch files older than a minute from the inbox and keeps fresh ones`, `the sh timeout receipt reads every key with one grep`, `the sh timeout receipt preserves ordered plain metadata and the session gate`, `a timed-out prompt classifier saves a metadata receipt that marks a board request but not a folder named agent-board`, `a report hook whose reporter runs past its deadline is never queued`, `only the hook worker carries the hook-errors.log temp sweep, not the bootstrap or the SDK guard`.
