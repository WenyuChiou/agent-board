- **The board keeps its saved records and files to a fixed size, and a session start does the same work on a store four times as big (#373).** Ended agent records go after 3 days (30 while still at work); a session's mirror after 7 days, or 30 while it has open steps; neither goes while its block is still on the board, and no record is removed unless progress.md is there, not empty, not cut off, and has the same time and size right before the delete as when it was read (a file half written at the read looks like a board with fewer blocks); reminders told are keyed by a short hash of the question and its words instead of the words themselves, kept 3 days and at most 500; the copies of other agents' files (`generated:`) go once the connect worker keeps its own record; the store's cut-off temporary copies go after a day and inbox files given up on a week after they were set aside; a month's journal and archive go on in a new part at 1 MB, and the count of today's work reads only the last part. The inbox of other agents' turns (`progress-inbox/`) holds at most 1,000 turn files or 1.5 MB: a reporter script, or the OpenCode or OpenClaw plugin, that finds it past either after saving its own turn removes the oldest turn files first, never a file a session has taken, one set aside as `.failed`, or a temporary file, and records how many it removed, together with the turns the reporters' 2-day cleanup removes, as one line `<UTC time> <count> <reason>` for each removal in `progress-inbox/dropped.log` (once the file passes 6 KB, folded to one line per UTC day and reason, keeping days on or after the UTC day eight days back). A session start reads at most 25 store values to prune, walking the store a stretch at a time, and the hand-kept tasks seen done are one store value instead of a key each; a time kept for a task no longer done is let go, so a later task of that name waits its own day. The pane, the status line, the reminders and `progress.html` share one built view per change. A store still at or over its hard cap of 1.5 MB (1572864 bytes) after those rules loses its oldest ended agent and mirror records that are not on the board, oldest write first, until the bytes left are under the cap; never a record whose block is on the board, nor a mirror with open steps of a session on the board, and only under the same guard (the same board read, and the same time and size right before the delete). It is the one pass that reads more than a batch of store values, and only when the store is over the cap. Every store record removed, by the age rules or by the cap, is counted by kind (`agent`, `mirror`) and UTC day in one small store value, `prunedCounts`, which keeps the last 7 days. The pane and `progress.html` say in one line what was cleared in the last 7 days, with the inbox turns the writers dropped (from `dropped.log`) added ("Cleared 12 old agent records and 340 unread inbox turns in the last 7 days", in English, zh-TW and zh-CN), and show it only when something was cleared. A hand-kept task or a step waiting on the person is never removed by a size rule: past a size limit the board warns and says so. Each `agent:` and `mirror:` record the pane saves carries a short tag of the path of its board, so a second board sharing the store uses the short lives and cap only for its own records (another board's record or one with no tag goes only on the 30-day rule), and this board's record dated more than a day ahead counts as expired unless its block is on the board; each record is read again right before it is deleted and kept if it was written since; the prompt receipts, confirmed completions and unwritable journal lines of a record (`agentPrompt:`, `completion:`, `pendingJournalBad:`) go with it, by the age rules and by the cap, and are counted with it, not a second time. An inbox file set aside as `.failed` is kept 7 days from the time the pane recorded for it (written before the file is moved), a file with no time recorded gets the time of the first sweep that sees it and never its own date, and the saves of that record go one after another, so the sweep does not write back an older copy over a newer time; the notice says the file is kept for 7 days. The store warning no longer says old records are being cleared: it says that only records of sessions whose block has left the board are. A time that comes back from another session for a task no longer on the board does not win over the new time of a later task of that name. Until 0.25 a reminder is also kept as told under the key 0.23.x sessions read, so a 0.23.x session sharing the store does not repeat a question a 0.24 session already told. On Windows, a file another session already removed no longer stops the rest of a batch of removals. The temporary copy a reporter leaves in the inbox when it is cut off (`<turn name>.tmp`, the name all of the sh, PowerShell and OpenCode reporters use, or `<turn name>.json.tmp`) is removed once it is over a day old, in the same removal as the store's own temporary copies; it is a partial write and not a turn, so it is not counted as cleared, and a `.json`, `.receipt`, `.taking` or `.failed` file is never taken this way. This branch removes no question or ledger file, so none is counted (the redundant capture and proof files #156 removes are not counted either). A run of 30 simulated days holds the store, reminder, journal and archive caps at each day's end, counts every removed record, adds the turns `dropped.log` records to the cleared line, and keeps every question source copy it made. A trimmed dropped.log preserves each kept UTC day's age and cap totals, so the pane keeps its true seven-day count. Every writer excludes its newly saved turn from cleanup even when the other turns are newer. Another board's ended agent and closed mirror records expire only after 30 days. A full store-cap pass that leaves the store over the cap waits six hours before reading all candidates again. Overlapping sweep and drain saves preserve both changes through the set-aside save queue. The sh fold works on old mawk without brace intervals. All writers share the 6144-byte fold threshold and eight-day cutoff, retain a moved copy if its fold cannot be appended, and recover unclaimed copies more than a minute old. The reporters remove turn files only through the counted two-day cleanup and the cap; their scratch files a minute old are not turns and are not counted. The six-hour store-cap hold saves only its time after removals were tried, skips busy passes and absent-key deletes, and tolerates store failures without losing cleared counts. Untagged agent and mirror records skip the future-clock check and keep their 30-day life. A saved `storeId` makes the cap and warning measure the one file whose saved top-level `storeId` equals this copy's id when a development copy has another beside it. When none or more than one matches, or any candidate cannot be read or parsed as JSON, the cap and size warning wait; the files are checked again after an hour or when the list of file names changes. A lone file is measured without reading unless it was left after a failed identification or after the remembered file left the listing; files all at or under 1.2 MB are measured without reading too. A remembered file leaving forces a fresh check when a file next exceeds 1.2 MB. Record sizes count their full indented UTF-8 bytes, so CJK records free their true share. Reminders told are trimmed even when there is nothing new, and an unchanged list is not written. A session start checks 10 records so rereading expired ones stays within its read budget. Windows removal batches keep going after a missing file returns a failing exit code. Reporter turn-removal failures log `CLEANUP_FAILED` once per cleanup pass, not once per file, except when another reporter already removed the file. Both archive paths remove legacy `done:` keys so a later task of the same name waits its own day.
