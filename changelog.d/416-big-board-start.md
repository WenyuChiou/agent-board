- **A board with thousands of question files no longer gets the pane unloaded at session start, and the inbox no longer waits behind a question pass for each session or behind the clean-up of the question files (#416).** On a copy of a real board with 5,527 question copies and 515 retirement proofs, the 0.24.0 candidate took about 112 seconds before the first reply (0.23.5: about 52) and drained none of 418 inbox files in 10 minutes. Four things held it up. First, before it writes the question ledger, each pass checked which open questions still need a copy kept by serialising every copy again for every open question, with no trip to the host in between; on a big board that ran past the 5 seconds Claude Code waits for the mod's heartbeat (#371), so the mod was unloaded in the middle of the first poll. Each copy is now serialised once a pass, and questions are found by id instead of by searching the list for each one (also when the copies are merged into the ledger, and when the turns kept from the inbox give a question its age); working out which questions are answered now takes each step's words, each question's hash and the retired set once a pass, not once for every pair. On a synthetic board with 300 waiting questions and 5,800 question files, the longest stretch without a host call at start and through the inbox looks after it went from about 3.5 seconds to well under one second. Second, each pass kept the retirement proof of every question it retires again, three host calls apiece, even when the proof was already on disk; a pass now leaves out a question whose proof it already holds, so each proof is read once and never checked again. Third, for every session a look at the inbox took turns from, it settled the answers those turns prove, polled the board and kept the session's questions, each a full question pass, all inside the queue that all of a session's writes go through; it now does each once for the whole look, after all its turns are on the board, and polls outside the queue. Fourth, the clean-up of the question files (#156) read and checked every copy and proof again inside that queue too, and session start put it there ahead of everything else. The clean-up now decides from the copies and proofs the polls already read and remember by name, size and time, outside that queue. Before it removes anything it reads again from disk only the files it is about to remove and the files that let them go (the retirement proof of an answered question, or the newest newer copy that holds everything an older copy holds); if any of them fails its check, nothing is removed that sweep. Only the removal goes through the queue, while the ledger and the acknowledgement list are still the ones the choice was made from. At session start the clean-up runs after the first look at the inbox; `/progress tidy` and the pane's archive still finish it before they answer, and an hourly sweep with nothing to remove reads no question file. What a pass keeps, retires and writes is otherwise unchanged, and so is what the clean-up removes: the same rules, at most 200 files a sweep, fifty to a process. The board script's `--watch` and `--serve`, which write the same ledger, use the same checks.
  Tests: `a question pass over 1,000 open questions and 5,600 copies works out the copies to keep and the questions to retire well within a second`, `each capture that can go is named with the file that lets it go: its retirement proof, or the newest newer copy that holds what it holds`, `a session start on a board with 300 waiting questions and 5,500 old copies, and the inbox looks that keep 30 new questions, never go a second without a trip to the host`, `question passes over a board whose retirement proofs all exist read each proof once, and neither write a proof nor ask whether one exists`, `a look at the inbox that takes questions from ten sessions keeps them all in one question pass`, `on a board with 5,500 question copies, 500 proofs and 400 inbox turns, the inbox drains from the first look while the question files are trimmed`, `an hourly sweep reads again only the question files it removes and the proofs that let them go, and one with nothing to remove reads none`, `pruning reads the files afresh, so a copy damaged on disk since the polls looked is not the newer copy`, `pruning reads the proofs afresh, so a proof damaged on disk since the polls looked stops the clean-up`, `nothing is removed when the ledger changes between the choice and the removal, and the files go at the next tidy`, `nothing is removed while the acknowledgement list cannot be read, and the files go once it can`.
