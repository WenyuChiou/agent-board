- **A board with thousands of questions and question copies no longer gets the pane unloaded during session start (#416).** Before it writes the question ledger, each pass checks which open questions still need a copy kept. It did that by serialising every copy again for every open question, with no trip to the host in between. On a synthetic board with 300 waiting questions and 5,800 question files, the first poll at session start went 4.5 seconds without a host call; on a larger board that ran past the 5 seconds Claude Code waits for the mod's heartbeat (#371), so the mod was unloaded in the middle of the first poll and the inbox, the archive and the clean-up never ran. Each copy is now serialised once a pass, and questions are found by id instead of by searching the list for each one (also when the copies are merged into the ledger, and when the turns kept from the inbox give a question its age). The same start now goes at most about a quarter of a second without a host call, and working out the copies and retirements for 1,000 open questions and 5,600 copies takes tens of milliseconds. The board script's `--watch` and `--serve`, which write the same ledger, use the same check. What a pass keeps, retires and writes is unchanged.
  Tests: `a question pass over 1,000 open questions and 5,600 copies works out the copies to keep and the questions to retire well within a second`, `a session start on a board with 300 waiting questions and 5,500 old copies never goes a second without a trip to the host, and writes no copy it already has`.
