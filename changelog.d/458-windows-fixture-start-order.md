- **The messaging tests start their page in the order `--serve` does on Windows (#458).** `--serve` makes its private address folder before it starts the page, so the page's 10 s start window begins with PowerShell already loaded. The test fixture started the page directly, so the first PowerShell start on a fresh Windows machine (2–3 s in traced CI runs) fell inside that window; three starts on `main` timed out with no trace, and this is the likely cause. The fixture now makes the folder first with the same call, and a slow or failed start reports each phase of the page's start: the stdout length, stderr, exit, every `whoami`, `icacls` and PowerShell start with its time, listen and the address.
  Tests: `receive=false renews an authenticated lease without claiming queued work`, `busy native owners remain connected and can send: codex`, `busy native owners remain connected and can send: antigravity`.
