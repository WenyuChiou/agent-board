- **Page / Windows start** · On Windows the page start runs one PowerShell instead of four and gives it 30 s, so a slow first PowerShell start no longer ends with "Couldn't protect the board page's address file for this account" and no page. A folder or address file another account can use, a link, a hard-linked file, a wrong owner and a second grant are still refused. The messaging tests print one line when a page start took over 5 s or failed (#468).
  Tests: `a cold Windows page start runs one PowerShell for the command and the server it starts together, and one more only to read again a folder it took another account's grant from`, `a Windows page start whose first PowerShell start takes over 10 s still opens the page`, `a Windows page start gives PowerShell a 30 s guard and leaves icacls and whoami at 10 s`, `a Windows server child reuses the folder its command checked and checks any other folder in full`, `a Windows server child refuses a runtime junction even when it is handed the identity of its target`, `runtime access list validation without an owner rejects other accounts, extra grants and the wrong flags`, `Windows page token writes explicitly own a new file before they read its access list or write the token`, `Windows page start discards a new address file whose owner cannot be set or whose access list is not private`, `a Windows page start opens the page when an old page removes its address file during the access check`, `a Windows server child checks the folder in full when its handoff is missing, malformed or for another folder`, `Windows page access lists are saved inside the private runtime folder and the scratch folder is removed afterwards`, `a Windows page start leaves its new address file and its folder owned by this account`.
