- **Codex / Windows hooks** · On Windows, the Codex hook command for a Node path with a space and no short 8.3 name now passes on its start time like the Antigravity one, and both encoded launches double curly single quotes, which PowerShell reads as quotes, so a home folder with `’` no longer skips the hook. A path word with a curly double quote goes through the encoded launch. Running setup again keeps the Node program it wrote last time when that is still the same file, so a slow short-name check cannot change the command. When the command does change, Codex treats the hooks as new and does not run them until they are trusted again: run setup's `--codex-trust --codex-bin <full path to codex>` once more, then the same with `--apply` (#625).
  Tests: `on Windows a Codex hook command for a Node path with no quote-free name runs from PowerShell and cmd through an encoded launch`, `on Windows a Codex hook command whose paths hold curly quotes runs from PowerShell and cmd`, `sharing the encoded launch with Codex leaves the Antigravity command the same bytes`, `on Windows setup keeps the Node program it wrote last time when the short-name probe cannot run`.
