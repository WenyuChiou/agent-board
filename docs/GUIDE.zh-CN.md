## 开始使用

工作交出后由来源明确回报：Claude Task 工具在每个交出的步骤加 `metadata: {"handoffTo":"承接方名称"}`；明确改为 pending／in_progress 可接回。回合摘要用 `HANDOFF` 记录承接方，`NEXT` 保留交出的工作；其他 reporter 写 `[-] 工作 — 已交给承接方`。来源保留取消项目，不再提示 Continue，也不重复计入承接方的工作。交接计划、发出消息、模型摘要或进度更新都不证明送达，也不批准动作。

使用 Node.js 18+ 与 repository checkout。永久变更先预览、批准再应用：

```sh
node scripts/setup-agent.mjs
node scripts/setup-agent.mjs --apply
```

自动检测识别 host 配置，不代表 session 在线。尚无配置的已知 host 可用 `--agent <name>`；`--agent all` 预览全部目标，不会安装 AI 应用。[安装说明](SETUP.md)列出路径与 adapter 范围。

新独立安装使用 `~/.agent-board/progress.md`，现有安装保留原文件；`--progress-file /absolute/path/progress.md` 可明确指定。普通本地安装不需选择另一台电脑的看板。

读回定义，完成 host 的信任／启用。Codex 可在用户批准后执行限定信任，详见 [Codex](CODEX.md)。已打开的 session 可能需要重新加载。CLI、桌面 App、IDE 分别验收。

## 其他 agent

共享安装器写入看板、skill 及已实现的原生 adapter，不需要 Claude Code 或另一个模型。[支持范围](SETUP.md#native-status-adapters)会区分已安装与待实现项目。

支持的提示 hook 会在下次收件箱轮询时，把已有 agent 的问题标为已回答并切回工作中，不调用模型。旧版收件箱事件若来源时间较旧、相同、不明或无效，就不更改，也不创建或恢复区块。回执必须读回确认才移除收件箱输入，失败会保留重试。`/progress connect` 更新 hooks，`connect remove` 一并移除；OpenClaw 必须由 host 明确标示 `external_user` 来源。[提示事件契约与检查](validation/2026-10-19-prompt-hooks.md)列出支持范围及限制。

只读预览会略过提示元数据，保留尚未整理的汇报与问题。单凭提示时间或文件修改时间，不能证明汇报已处理。

OpenClaw、DeepSeek Harness 已有独立状态 plugin 与原生 skill；Grok 新提示会切回工作中，OpenCode 遵循配置目录覆盖。[跨 host 验收](validation/2026-10-19-portable-hosts.md)区分隔离回调／SDK 检查与未执行的原生测试。hooks 不会安装收信通道；接到同一私有消息目录的 agent 共享回执与去重记录，任务归档不会清掉消息 ID。

原生 hooks 汇报活动，不推测任务步骤。Codex Stop、Antigravity Stop 代表等待下一轮，不是对话关闭或任务完成。原生新提示／启动会重新激活同一区块。任务标题、步骤、阻塞及完成由 agent 明确汇报，且只能绑定自身可证明的 session。缺少 host context 时，不猜 ID、不读对话来拼凑汇报。

旧进度卡片不能证明进程仍在运行；应用开着，也不能证明该 session 已加载 hooks 或注册消息 adapter。[原生验收记录](validation/2026-10-19-native-hooks.md)分别记录这些能力。

## 每个 agent 里都看得到看板

使用已安装的 skill，或安装器打印的确切程序路径：

```sh
node ~/.agent-board/agent-board.mjs --serve
node ~/.agent-board/agent-board.mjs --watch
node ~/.agent-board/agent-board.mjs --chat
node ~/.agent-board/agent-board.mjs --html
```

| 模式 | 结果 |
| --- | --- |
| `--serve` | 交互网页与可复用的本地后台服务 |
| `--watch` | 终端看板：方向键／Enter 选择，`x` 勾选，`d` 确认完成，`a` 归档，`h` 隐藏，`u` 恢复，`i` 闲置工作，`c` 复制，`o` HTML，`q` 退出 |
| `--chat` | 精简文字；不开网页、链接或浏览器、不写文件 |
| `--html` | 生成并打开只读网页，不能发消息 |

聊天模式先列问题，再列尚未整理的进度汇报与来源时间。汇报不代表工作完成或连接在线；已领取或处理的收件文件不会重复显示，也不会只因 hook 时间更新就隐藏待处理汇报。超长内容会显示省略数量，聊天模式不写文件。

加上 `--lang en`、`zh-TW` 或 `zh-CN` 选择语言。Windows／自定义安装请使用实际打印的完整路径。Codex 的入口是 `$agent-board`，OpenCode 安装 `/board`；其他 host 须先加载已安装的 skill／command。

### 看板的网页

已隐藏的同一问题不会因其他步骤移动或空白变化而重现。相同文字的问题各有标识；数量改变时无法确定对应，因此会重新显示，不会继承另一题的隐藏标记。看板观察到问题已解决或移除后，再次提出会得到新的标识；若报告直接以完全相同的文字重新提问、没有可观察的状态变化，看板无法推断这次更新。仍可使用「重新显示」。隐藏不代表回答、批准、完成或消息送达。

Claude 明确再次提问时，即使文字相同，也会更新该问题的标识，不需等中间的重新整理。进度文件会随该步骤保留一个修订注记，看板不显示这项 metadata；其他已隐藏的问题和无关更新维持原标识。上述观察限制仅适用于既无状态转换、也无提问来源修订信号的报告。

本地标识记录存于 `progress.md` 旁的 `progress-questions.json`，与 `progress-answered.json` 分开；移动看板时请保留两者。旧的按位置标记会在完整报告稳定后迁移，仅保留同一范围内规范化文字唯一相符的问题；重复或无法对应的原始标记仍保留，但不隐藏未来的新问题。迁移标记可避免标识文件的写入丢失后错用旧标记。标识文件损坏或无法写入时保留原文件，新的隐藏操作会显示失败。聊天与单次读取不写迁移文件；未答问题在恰好三天内维持显示；超过三天到恰好七天改为一组提醒，超过七天移出可处理计数，仍可在「更早、尚未回答的问题」展开查看完整来源与时间。查看不会重设问题时间。终端按 `l` 查看较早问题，纯文本使用 `--all`。手动任务、自己运行中的 session、仍在线的外部 session 与收件箱问题共用策略；已停止、已结束或已完成 session 的问题会离开「等你处理」，随所属任务留在已停止区或「最近完成」。已停止的 session 删除或改写的问题，仍可在「更早、尚未回答的问题」中查看。点「标为已处理」可关闭单个问题。标为已处理后一直有效，直到 agent 勾掉或删除那个步骤、或任务改名；之后同样的问题可以再出现在「等你处理」。时间从持久保存的首次观察开始，不用心跳或导入时间；未知或未来的观察时间保守维持显示。只读聊天与单次读取使用已有基准，不建立基准。

备份或移动时也请保留 `progress-questions-retired-*.json` 与 `progress-questions-consumed-*.json`。这些不可变记录只含版本、种类与不透明哈希，避免旧文件写入让已退役的标识或已迁移的隐藏标记复活。它们不随时间或工作归档而删除。记录无法读取、不完整或无法写入时，先停用隐藏直到存储恢复；宁可多显示问题，也不错用旧标记。

侧栏、终端和网页以任务和 agent 识别工作，不显示连接清单或对话 ID；支持的续接命令仅在操作时复制。

问题排最前面，展开工作可看步骤。可勾选手动步骤、归档、贴入有效区块、复制回复或续接命令、标记已读及恢复。已读只改本地隐藏列表，不传话；实质不同的新问题会再出现。当前没有通用任务编辑表单。

**确认完成**一次勾选所有未完成步骤，保留已取消步骤。即使尚无来源缓存，后续 prompt 更新也保留这些取消项目；来源的新报告可取代该快照。可按侧栏／网页按钮，或在终端选取工作后按 `d`。仅适用手动工作，以及已结束或超过 12 小时未写入的 agent 区块；工作已变动或仍在运行时会拒绝。每个新勾选都记入日志；区块会设为 `state=done` 并更新时间，再依原有等待期归档。不向 agent 传话，`progress.html` 仍只读。

本地后续状态更新会保留已完成步骤；新的明确工作报告仍可带入新工作。

贴入进度保留来源时间。重复内容不变更；较旧或同时间冲突的进度会拒绝。无效或超前的时钟须先修正；原有进度时间不明时，须比较两份内容后确认取代。修复方式见[远程汇报](REMOTE_REPORTERS.md)。

卡片只有在确切 session 的 adapter 在线时提供发送，否则复制或自行打开 agent。[消息说明](MESSAGING.md)区分设置、真正回复、重复、冲突及超时。安装不会任意接管已打开的对话，普通回复也不能批准工具、信任或 PR 合并。

`--no-open` 只打印网址，不打开浏览器。关标签页不会停止本地服务，再运行同一 `--serve` 即可重开。**关闭看板**才会停止；若正在发送，请等完成。默认不会闲置关闭，`--idle-minutes 30` 才启用。旧版 `--allow-resume` 会明确启用已结束 Codex／Grok 的重新启动，默认关闭，也不会用作实时消息的回退路径。

#### 在手机上

网页的布局适合手机。要从和电脑连同一个 Wi-Fi 的手机打开，运行 `node ~/.agent-board/agent-board.mjs --serve --lan`：除了电脑本机的网址，它还会打印网页在你网络上的网址和它的二维码，用手机相机对着扫就好。电脑有不止一个网络地址时，用 `--lan 192.168.1.23` 指定一个。Windows 可能会问要不要让 Node.js 使用网络：在专用网络上允许，并确认 Windows 把你的 Wi-Fi 算作专用网络（刚连上的网络它会先当成公用网络），不然手机连不到网页。跨网络访问须另行设置远程连接。

网络上的网页有这些限制：

- 只有加了 `--lan` 才开，只开在电脑的私有地址上（开头是 192.168、10，或 172.16 到 172.31 的地址，绝不是公网地址），也只响应发到那个地址的请求。
- 它的网址带着自己的一把钥匙，不是电脑本机网页那把。拿到这个网址或拍到二维码的人，在它关掉之前都能用这个网页，所以只在信得过的网络上用，比如家里的 Wi-Fi，不要在咖啡店的。
- 在网络上，网页走的是没有加密的 HTTP，同一个 Wi-Fi 上的其他设备可能读到传过去的内容，包括 agent 的回答。所以手机可以勾步骤、归档、标成已回复（和重新显示）、复制、贴上区块和关闭看板，但不能回复 agent：回复会在电脑上运行一个程序，所以手机只显示答案让你复制，再从电脑本机的网页发出。
- 10 分钟没有手机来看就会关，电脑本机的网页关掉时也跟着关。开着的时候再运行一次 `--serve --lan`，拿到的是同一个网址。

开放前请读[安全说明](../SECURITY.md)。

## 进度文件

`progress.md` 是存储数据，不是 UI。每个 agent 拥有自己的区块，不覆盖其他 session。格式支持英、繁中、简中关键词，标记、所有权与写入读回规则见 [FORMAT](FORMAT.md)。

共享文件不会自动跨机同步。[远程汇报](REMOTE_REPORTERS.md)是另外选择的流程。`dot` 标签或贴上的区块不能证明真正 dot 已连接。

## 可选 Claude Code 侧栏

需要 Claude Code 2.1.287+；离线 CI 使用 2.1.301：

```sh
claude plugin marketplace add WenyuChiou/agent-board
claude plugin install agent-board@agent-board
```

打开新 Claude Code session，使用 `/progress`。侧栏镜像 Task 工具，也可通过它的模型整理回合。问题与决策显示于任务上方；侧栏跟随 Claude 主题，网页跟随系统主题，除非你在网页上选了亮色或暗色。

Claude 桌面 App 会显示底部状态栏；`/progress` 会提供可回答问题、归档工作的看板网页，交互网页无法启动时则打开只读网页。网页启动最多约需半分钟，期间底部状态栏会显示正在打开。交互网页需要由 `/progress connect` 安装看板脚本，或在下次会话开始时更新。使用同一份已安装的看板脚本的会话与 agent 会共用运行中的网页。`/progress` 打开的网页在最后一个标签页关掉 30 分钟后关闭，再运行一次 `/progress` 就有新链接；你自己用 `--serve` 打开的网页按它自己的设置。`/progress` 会换掉用 `--allow-resume` 打开的网页，除非那里还有回复正在发送；需要接续回复时，之后再运行一次 `--serve --allow-resume`。Claude Code CLI 则显示侧栏。

| 命令／输入 | 操作 |
| --- | --- |
| `/progress connect`、`connect status`、`connect remove` | 可选 plugin 连接、上次状态、移除 |
| `+ 求职: 研究驻点 截止 11-20; 草稿; 提交` | 侧栏快速新增，也可用 `/progress add …` |
| `/progress open` | 生成并打开只读 `progress.html` |
| `/progress tidy`、`/progress sync` | 归档符合条件工作；重读 Task／PR |
| `/progress report`、`/progress today` | 复制周报／日报 |
| `/progress lang en`、`zh-TW`、`zh-CN`、`auto` | 侧栏语言 |
| `/progress notify on`、`off` | 桌面通知 |

可选连接器需要 Node.js 18+；迁移前请重新加载较旧的 plugin 会话。原生 worker 跨数据目录共用安装锁，持续记住移除停用意图，并保留外部修改。侧栏与轮询先启动，版本检查在后台进行；缺少 Node 或设置记录损坏时不修改设置。`connect status` 表示设置结果，不证明原生执行。

可选的 `scripts/setup.sh`／`scripts/setup.ps1` 处理 Claude 专用 Task 工具／profile 与 marketplace 配置。修改 profile 前先检查范围；独立安装不需要这些脚本。旧 plugin inbox 连接器可保留对话数据并调用 Claude 整理，和只记活动 metadata 的独立 hooks 不同。[安全说明](../SECURITY.md)。

## 它怎么保持整齐

可选侧栏在 session 开始与每小时清理：完成区块等 12 小时，其他已停／过时区块等三天。持续运行的 `--serve` 网页也每小时整理一次。手动工作每个步骤都是 `[x]` 或 `[-]`，且被观察完成满三天后，才计入可归档数量；0.24.1 的自动整理只计数，不移走任何手动工作。详细信息行会显示“可归档 N 个已完成的任务”；数量为零时不显示。工作中或等待中的 agent 区块，最后写入后 12 小时内仍算运行中；侧栏、终端与网页会说明暂不能归档，整理也会保留。停止或结束后，展开工作即可立即归档。 自动整理归档仍有 `[?]` 的区块时，只有在保存并读回与明确归档相同的完整问题快照后才会归档，而且要等够久：已结束或已完成的区块满三天，仍在工作或等待中的区块则是满七天都没有新报告；快照存不了就保留原处。问题会保留，列在“更早、尚未回答的问题”下，仍可回答、隐藏或再显示。明确归档任何时候都必须先有这份快照，来源移走后仍可找回；存储失败便保留来源。

运行 `node ~/.agent-board/agent-board.mjs --tidy` 可在没有 Claude session 或网页时，按正常等待时间整理一次；不会安装计划任务，也不会写入 `progress-seen.json`。侧栏、`--watch` 或 `--serve` 会记录手动工作首次被观察完成的时间，以及三天规则首次运行的时间。三天从两者较晚的时间起算，让 0.24.0 就已完成的工作从升级后再等三天。电脑若只运行 `--tidy`，不会写入启用规则的保留记录，缺少这笔记录便不计数。未知、未来或读不到的观察时间都保留手动工作；`--tidy` 仍可归档等待时间已到的 agent 区块。网页的每小时整理若读不到观察文件，便跳过该次整理，不写入任何文件。

在侧栏或网页按“清理”（Clean up），会归档完成满三天的手动工作，正好就是数量行计算的那些，再加上一般整理会移动的代理区块。先写入同一组每月归档文件，再从看板移走；未满三天、未完成或有 `[?]` 步骤的工作会留下。若读不到完成时间记录，清理不会归档任何项目，也不会写入任何文件，并会说明原因。0.24.1 的无人操作整理（侧栏启动与每小时、`--tidy`、网页每小时）只计数，不移走手动工作。侧栏的“现在归档”与 `/progress tidy`、网页的“现在归档”，以及任务行的“归档”，仍可立即把完成工作移到每月归档文件，不会删除工作。侧栏与网页在大小警告旁显示一个“清理”按钮，只要可归档数量大于零也会显示，即使小看板没有大小警告。数字及可归档数量放在详细信息行。终端看板、聊天和 `--html` 也显示详细信息，但没有按钮。

超过 12 小时没汇报的卡片可能显示已停，这是数据过时判断，不是原生进程检查；真正新事件／汇报会刷新。超过七天没动的工作折叠，不修改区块；`--all` 或闲置开关可展开，快到期的工作保留显示。已结束或过时的对话会移至独立的已停止区，不再计入进行中；未回答的问题会离开「等你处理」，随任务保留，到期或闲置也一样；已完成 session 的问题留在「最近完成」中，移出后改到已停止区。在面板上点「标为已处理」可关闭单个问题；`--all` 或 `i` 可展开闲置和已停止工作。

侧栏存下的记录（plugin 的 store 文件，在 Claude 配置文件夹的 `plugins/store` 下）也有固定的大小。已结束 agent 的记录在最后写入三天后清掉，session 存下的任务清单在七天后清掉，还有未完成步骤的留三十天；区块还在看板上的记录一律不清。每条记录都带着它所属看板路径的短标记，所以看板只对自己的记录用较短的期限：同一台电脑上另一个看板的记录，要满三十天才会被清掉（0.24 以前存的记录没有标记，也是满三十天才清）；看板自己在时钟错误时写下、日期比现在晚超过一天的记录，只要区块不在看板上也会清掉。侧栏标成 `.failed` 的收件箱文件，从标记那一刻起留七天，不看文件本身的日期。收件箱里回报程序没写完就中断、留下的 `.tmp` 临时文件，满一天就清掉；它是写到一半的文件，不是回合，所以不计入已清除的数量。清完仍超过 1.5 MB 时，会从没在看板上、已结束的 session 记录由旧到新再清，直到低于上限；手写的工作与等你回复的步骤不会因大小规则被删。其他 agent 的收件箱最多放 1,000 个文件或 1.5 MB：写入端丢掉最旧的，并把数量记在 `progress-inbox/dropped.log`。侧栏与 `progress.html` 会用一行说明最近 7 天清掉了什么，例如“最近 7 天清掉了 12 条旧的 agent 记录和 340 条还没读的收件箱回合”，有清掉东西时才显示。记录超过 1.2 MB（警告会说只有区块已离开看板的 session 记录会被清掉）或 `progress.md` 超过 512 KB 时也会警告。

## 更新和卸载

独立安装：将干净 checkout 更新到指定版本，预览 `node scripts/setup-agent.mjs`，再应用已批准范围。修改过的文件列为冲突，不覆盖。host 可能要重新加载；不安装自动更新器或开机服务。

用已安装程序预览／应用目标移除：

```sh
node ~/.agent-board/agent-board.mjs --codex-remove --agent <name>
node ~/.agent-board/agent-board.mjs --codex-remove --agent <name> --apply
```

`--codex-remove`、`--codex-doctor` 是沿用的维护名称，可搭配各目标。先关闭该看板。只移除未修改的自有定义／文件；其他目标还需要的共享文件保留，进度、session 记录、归档、日志及用户修改也保留。

可选 plugin 请先在仍安装时运行 `/progress connect remove`，完成报告的清理后，再运行 `claude plugin uninstall agent-board@agent-board`；marketplace 用 `claude plugin marketplace remove agent-board` 移除。更新用 `claude plugin marketplace update agent-board`、`claude plugin update agent-board@agent-board`，之后重新加载 plugin。

### 从旧名称换过来

0.10 前的可选 plugin 名称是 `project-progress@claude-progress-pane`。移除旧 plugin／marketplace，安装上方新名称；若使用其连接器，再于 Claude Code 内运行 `/progress connect`。保留原进度文件。独立安装不需要 Claude 迁移。

## 常见问题

### 可以只从一个 agent 开始吗？

可以，使用通用安装器从支持的任一 agent 开始，不需要另一家 AI。原生 hooks 依 host 而异；看板和明确报告自身进度的入口共用。

### 我是从 Codex（或其他 agent）装的，它看得到 Claude Code 在做什么吗？

可以，只要各 session 报告到同一个本地进度文件。独立 reporter 不需要 Claude Code 就能更新自己的区块；可选侧栏也读同一文件。打开看板和接上原生收信是两件事。

### 换了一台电脑，东西都没了吗？

不会丢，但也不会自己搬过去：`progress.md`、收件箱和 hook 都只在各自的电脑上。在新电脑运行通用安装器，再重启 agent 就好。要带上以前的记录，就把你选用的 `progress.md` 和旁边的 `progress-archive-*.md`、`progress-journal-*.md` 复制过去。

想让两台电脑共用一个面板，就在两台都把 `CLAUDE_PROGRESS_FILE` 设成同步文件夹（OneDrive、Dropbox、iCloud）里的同一个文件，再在每台电脑各运行一次 `/progress connect`：自动连接只会跟着默认的进度文件，或你上次手动连接的那一个。一次只用一台最稳：两台同时写，同步软件可能会留下冲突副本。

### 某个 agent 没出现。

1. 执行 `node scripts/setup-agent.mjs` 预览当前 host，查看冲突与 `adapter-pending`。
2. 按 host 要求重载，完成限定范围的原生 hook 信任／启用，再读回确认。
3. 由该 session 使用自己的原生 id 报告，检查精确区块与更新时间；不要替其他 session 猜任务。
4. 另外观察新的原生生命周期事件。进度出现不代表可以反向收信，见[接线检查](MESSAGING.md#connecting-a-session-that-was-already-open)。

可选 Claude 插件另有 inbox 流程，该安装可用 `/progress connect status` 查询；独立状态 hooks 不需要 Claude 对话开着。

公开反馈问题时，请提供：

- 看板、Node.js（`node --version`）和受影响 agent 的版本；使用可选 Claude 集成时才附该插件版本。
- 操作系统、哪个 agent、做了什么、预期结果和实际结果。
- 已移除私人信息的安装／doctor 输出。

不要上传原始收件箱、进度或会话日志文件。分享输出或截图前，移除提问、回复、私人路径、token（包括看板链接和二维码），以及人名或项目名称。请另写一个小示例。`--chat` 只会尽力隐藏自身输出中的主目录路径和常见凭据格式，无法保证完整，也不会清理诊断文件。

虚构示例（填上版本，不需要真实对话）：

```text
操作系统：演示系统；看板／Node.js／agent 版本：<版本>
操作：在 demo-1 完成一个回合。预期：看板出现一行。实际：没有出现。
安装／doctor：<已检查并移除私人信息的状态>
```

私密或涉及安全性的问题，请通过 GitHub 的 [Report a vulnerability](https://github.com/WenyuChiou/agent-board/security/advisories/new) 反馈。详见 [SECURITY.md](../SECURITY.md)（英文）。

### 会把数据传出去吗？要花多少钱？

独立 reporter 只在本地保留挑选过的 session 元数据，不调用摘要模型。发信给在线 agent会使用目标 agent 的模型与额度。下列模型与对话访问适用于可选的 Claude 插件流程：看板文件保存在本机。通过你自己的 Claude Code 登录／模型访问，回合摘要会把提问和回复发送给 Claude Haiku；标题会发送该对话的第一个请求和步骤名称；交接行会发送最多 6,000 个字符的压缩摘要。面板的侧边提问框也会通过同一个登录，把你的问题发送给模型，根据这段对话的记录回答。这些调用使用该账号的额度或计费。面板会运行 `git branch --show-current`，装了 GitHub 的 `gh` 的话，也会用它查 pull request 和 CI 状态。默认只发给确切在线的对话；旧版 Codex／Grok 进程续接须明确加上 `--allow-resume`，使用该 agent 的权限和网络。独立 OpenClaw 插件禁用对话访问；可选 Claude 连接器则设置 `allowConversationAccess: true`。

`--serve` 默认只监听本机（`127.0.0.1`）；这台电脑上的任何程序只要有链接就能使用。`--serve --lan` 会通过带 token 的 HTTP 链接，在私有网络分享网页。token 是访问密钥，不会加密：同一网络上任何拿到 LAN 链接的人都能读看板、修改看板文件（包括导入区块），也能停止服务器。LAN 网页会拒绝启动 agent 的回复，也不显示恢复会话的命令。私有网络地址不代表咖啡馆或酒店的网络值得信任。不要分享链接或二维码。要停止服务，请按网页上的“关闭看板”按钮；若正在发送回复，请等完成后重试。只关标签页，后台服务会继续运行；空闲关闭须自行启用。看板服务器或 LAN 监听器每次重新启动都会生成新的 token，因此停止后旧链接就无法使用。文件变更、启动的程序、网络访问和 `--chat` 隐藏信息的限制，详见 [SECURITY.md](../SECURITY.md)（英文）。

### Windows 能用吗？

本地看板支持 macOS、Linux、Windows；原生 hooks 与消息按 host 和界面分别验收，见 README 的[支持的 agent](../README.zh-CN.md#支持的-agent)。独立 Windows hooks 使用 Node，不需要 `sh`。

### 以前用的是 `claude-progress-pane`。

插件在 0.10.0 改了名，不会自己换过去。按[从旧名称换过来](#从旧名称换过来)的步骤做就好，`progress.md` 不会动。

### 怎么卸载？

独立安装：先关闭看板，预览 `node ~/.agent-board/agent-board.mjs --codex-remove --agent <name>`，确认后加上 `--apply`。进度和历史会保留。可选 Claude 插件的卸载方式：

```sh
claude -p "/progress connect remove"
claude plugin uninstall agent-board@agent-board
claude plugin marketplace remove agent-board
```

第一行会断开其他 agent 的连接；先处理完列出的清理问题，再卸载插件。历史记录、汇报脚本和收件箱会留着。重试方式、已经卸载插件时的补救步骤，以及保留文件的位置，请看上面的[更新和卸载](#更新和卸载)。

## 问题排查

- **没卡片：** 检查路径、adapter、信任与重新加载；观察真正事件并读回确切 session 区块，不手动制造事件宣称通过。
- **不能发送：** 确切原生 session 需要受支持的在线 adapter，hooks 本身不等于可收信，桌面与 CLI 结果不可互代。
- **接线转述被忽略：** 接收者应告知授权或阻塞原因；RPC 成功或 ACK 不等于已观察到新进度。
- **读写失败：** 处理指出的文件／权限问题，检查进度与历史再重试；不先确认 owner 就删锁。
- **没有原生侧栏：** 非 Claude host 使用交互网页或终端看板，网页面板不等于原生侧栏。
- **写到一半被截断的工作：** session 写自己的区块时如果中途停掉（崩溃或被强制关闭），区块可能少了结束标记。看板会把它读成在它最后一行结束，按原样显示，并列在侧栏最下方的「看板状态」。要自己补上，就在它最后一行的下一行加上 `<!-- /auto session=<id> -->`；id 在区块的开始标记里。如果那个 session 先重写了自己的区块，新区块下方留下的几行会重复它旧的步骤：请自己删掉。

### 安全地报告问题

提供 Agent Board／host 版本、CLI／App／IDE、OS 与合成复现数据；只有可选 plugin 才需要 Claude 版本。不上传原始进度、inbox、归档、日志、session log、凭证或看板 token。[安全报告](../SECURITY.md#reporting-a-problem)。

当前 Codex hooks 尚未在 /hooks 批准时，可选连接器会保留受管理的报告指示。Codex 确认批准后，connect 会去掉这些指示，并记下这次批准对应的 hooks.json 与当时 Codex 的 config.toml。问不到 Codex 时（找不到可执行文件、响应太慢、出错、回答的格式这一版读不懂），只要这两个文件都没变，就沿用记下的批准。Codex 回答 hooks 未批准、已关闭或不在列表中，或问不到 Codex 而其中一个文件改过时（任何改动都算，包括在 /hooks 取消批准或关闭 hooks，这会改写 config.toml），connect 会把指示加回来。问不到 Codex、而找到的 Codex 可执行文件不是记下批准时的那一个（例如 Codex 升级后）或读不到时，也一样会加回来。Windows 上用 npm 安装的 Codex，检查时直接运行 npm 包内的 Codex 可执行文件，不经过 `codex.cmd`。status 查询信任，但不修改指示。

完整来源也保存在看板旁、按内容寻址的 progress-questions-source-*.json 文件。备份或移动时请保留整组 questions 文件。侧栏归档时（session 开始、每小时与侧栏整理；看板脚本的 `--tidy` 不会）每种文件（来源副本、retired 证明、consumed 证明）保留最新的 16 个，较旧的只有在 questions 文件或较新的副本已完整记下其内容时才会删除；可能是唯一记录的文件会留着，任何一个读不到时就一个都不删，一次整理最多删 200 个，其余留到下一次。同一次归档也只留最新的 3 个损坏的 questions 文件（questions 文件被截断或写坏时移到一旁的 `.torn-*` 副本），放超过一周的即使在最新 3 个之内也会删除；写到一半中断留下的临时副本放超过一天、且 questions 文件本身读得出来时也会删除。每次读取都合并所有副本，过期索引无法删除原始来源。清理与明确归档前必须成功写入并读回完整副本。end 事件只关闭连接，不代表回答问题；同一来源的多个问题与仅出现在 end 的问题都保留。副本损坏或无法读取时，拒绝清理来源与新的隐藏操作。
处理与解决后仍保留精确来源版本，因此重放旧的原始文件不会把已回答问题当作新问题；新的来源版本仍可被识别。
明确归档会把完整未答副本保留在较早问题区；来源意外消失时仍沿用正常年龄策略，未知时间的问题维持显示。
已结束、已完成或 12 小时没有回报的会话，其未答问题仍留在该会话的“已停止”行，同时会在“更早、尚未回答的问题”下列出一次，并显示距离第一次提出已过多久（不会少于该会话安静的时间），以及项目、agent 与任务。“等你处理”下面只有一行“N 个未回答，在已停止的对话”，点击会打开这份清单；问题不会移进“等你处理”，等待数量也不会改变，即使同时出现在“已停止”行也只算一次。清单在面板、网页与 progress.html 显示前十个问题，其余用“显示全部（N）”展开；终端看板则全部列出。“已回复，先隐藏”与“重新显示”可用在清单中的每个问题，包括保留自已归档会话的问题（目前还不能从看板回答这类问题，或把那个会话找回来）；这个版本之前已隐藏的问题保持隐藏、也不计入。
过期报告若仍使用相同的已知来源版本与问题文字，不会让已解决问题重新出现。明确更新来源版本或实质改变问题文字后，问题仍可再次显示。
终端与原生面板的提醒／较早问题区，仍有来源的问题可按「已回复，先隐藏」及「再次显示」，不会变更来源或重设时间。来源已消失的保留副本会标明仅供查看；网页的提醒／较早问题区也仅供查看，不提供隐藏按钮。
原生面板的回复若发送失败或被拒绝，问题维持未读。成功发送后仍会核对精确问题与来源；传送期间重新提出的问题不会被标成已读。既有问题移至保留区不会产生新通知。
