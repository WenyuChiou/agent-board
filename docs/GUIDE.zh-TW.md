## 開始使用

工作交出後由來源明確回報：Claude Task 工具在每個交出的步驟加 `metadata: {"handoffTo":"承接方名稱"}`；明確改為 pending／in_progress 可接回。回合摘要用 `HANDOFF` 記錄承接方，`NEXT` 保留交出的工作；其他 reporter 寫 `[-] 工作 — 已交給承接方`。來源保留取消項目，不再提示 Continue，也不重複計入承接方的工作。交接計畫、送出訊息、模型摘要或進度更新都不證明送達，也不批准動作。

使用 Node.js 18+ 與 repository checkout。永久變更先預覽、核准再套用：

```sh
node scripts/setup-agent.mjs
node scripts/setup-agent.mjs --apply
```

自動偵測辨識 host 設定，不代表 session 在線。尚無設定的已知 host 可用 `--agent <name>`；`--agent all` 預覽全部目標，不會安裝 AI 應用程式。[安裝說明](SETUP.md)列出路徑與 adapter 範圍。

新獨立安裝使用 `~/.agent-board/progress.md`，既有安裝保留原檔；`--progress-file /absolute/path/progress.md` 可明確指定。一般本機安裝不需選另一台電腦的看板。

讀回定義，完成 host 的信任／啟用。Codex 可在使用者核准後執行限定信任，詳見 [Codex](CODEX.md)。已開啟的 session 可能需要重新載入。CLI、桌面 App、IDE 各自驗收。

## 其他 agent

共用安裝器寫入看板、skill 及已實作的原生 adapter，不需要 Claude Code 或另一個模型。[支援範圍](SETUP.md#native-status-adapters)會區分已安裝與待實作項目。

支援的提示 hook 會在下次收件匣輪詢時，把既有 agent 的問題標為已回答並切回工作中，不呼叫模型。舊版收件匣事件若來源時間較舊、相同、不明或無效，就不更動，也不建立或還原區塊。回執必須讀回確認才移除收件匣輸入，失敗會保留重試。`/progress connect` 更新 hooks，`connect remove` 一併移除；OpenClaw 必須由 host 明確標示 `external_user` 來源。[提示事件契約與檢查](validation/2026-10-19-prompt-hooks.md)列出支援範圍及限制。

唯讀預覽會略過提示中繼資料，保留尚未整理的回報與問題。單憑提示時間或檔案修改時間，不能證明回報已處理。

OpenClaw、DeepSeek Harness 已有獨立狀態 plugin 與原生 skill；Grok 新提示會切回工作中，OpenCode 遵循設定目錄覆寫。[跨 host 驗收](validation/2026-10-19-portable-hosts.md)區分隔離回呼／SDK 檢查與未執行的原生測試。hooks 不會安裝收訊通道；接到同一私有訊息目錄的 agent 共用回執與去重紀錄，任務封存不會清掉訊息 ID。

原生 hooks 回報活動，不推測任務步驟。Codex Stop、Antigravity Stop 代表等待下一回合，不是對話關閉或任務完成。原生新提示／啟動會重新啟用同一區塊。任務標題、步驟、阻擋及完成由 agent 明確回報，且只能綁定自身可證明的 session。缺少 host context 時，不猜 ID、不讀對話來湊回報。

舊進度卡片不能證明程序仍在執行；應用程式開著，也不能證明該 session 已載入 hooks 或註冊傳訊 adapter。[原生驗收紀錄](validation/2026-10-19-native-hooks.md)分別記錄這些能力。

## 每個 agent 裡都看得到看板

執行過 `npm install -g @wenyuchiou/agent-board` 後，任何終端機都能使用 `agent-board` 指令；沒有安裝時，改用 `npx @wenyuchiou/agent-board`：

```sh
agent-board
agent-board stop
agent-board --chat
agent-board --help all
```

| 模式 | 結果 |
| --- | --- |
| `agent-board` | 就地開啟看板：桌面開視窗、SSH 在終端機開即時看板、agent 印純文字 |
| `agent-board stop` | 停止此進度檔案的看板網頁伺服器 |
| `--serve` | 互動網頁與可重用的本機背景服務 |
| `--watch` | 終端看板：方向鍵／Enter 選取，`x` 勾選，`d` 確認完成，`a` 封存，`h` 隱藏，`u` 還原，`i` 閒置工作，`c` 複製，`o` HTML，`q` 離開 |
| `--chat` | 精簡文字；不開網頁、連結或瀏覽器、不寫檔 |
| `--html` | 產生並開啟唯讀網頁，不能傳訊 |

聊天模式先列問題，再列尚未整理的進度回報與來源時間。回報不代表工作完成或連線在線；已取走或處理的收件檔不會重複顯示，也不會只因 hook 時間更新就隱藏待處理回報。超長內容會顯示省略數量，聊天模式不寫檔。

加上 `--lang en`、`zh-TW` 或 `zh-CN` 選擇語言。Windows／自訂安裝請使用實際印出的完整路徑。Codex 的入口是 `$agent-board`，OpenCode 安裝 `/board`；其他 host 須先載入已安裝的 skill／command。

### 看板的網頁

已隱藏的同一問題不會因其他步驟移動或空白變動而重現。相同文字的問題各有識別；數量改變時無法確定對應，因此會重新顯示，不會繼承另一題的隱藏標記。看板觀察到問題已解決或移除後，再次提出會得到新的識別；若報告直接以完全相同的文字重新提問、沒有可觀察的狀態變化，看板無法推斷這次更新。仍可使用「重新顯示」。隱藏不代表回答、核准、完成或訊息送達。

Claude 明確再次提問時，即使文字相同，也會更新該問題的識別，不需等中間的重新整理。進度檔會隨該步驟保留一個修訂註記，看板不顯示這項 metadata；其他已隱藏的問題與無關更新維持原識別。上述觀察限制僅適用於既無狀態轉換、也無提問來源修訂訊號的報告。

本機識別紀錄存於 `progress.md` 旁的 `progress-questions.json`，與 `progress-answered.json` 分開；搬移看板時請保留兩者。舊的依位置標記會在完整報告穩定後遷移，僅保留同一範圍內正規化文字唯一相符的問題；重複或無法對應的原始標記仍保留，但不隱藏未來的新問題。遷移標記可避免識別檔的寫入遺失後錯用舊標記。識別檔損壞或無法寫入時保留原檔，新的隱藏操作會顯示失敗。聊天與單次讀取不寫遷移檔；未答問題在恰好三天內維持顯示；超過三天到恰好七天改為一組提醒，超過七天移出可處理計數，仍可在「更早、尚未回答的問題」展開查看完整來源與時間。查看不會重設問題時間。終端按 `l` 查看較早問題，純文字使用 `--all`。手動工作、自己執行中的 session、仍在線上的外部 session 與收件匣問題共用政策；已停止、已結束或已完成 session 的問題會離開「等你處理」，跟著所屬工作留在已停止區或「最近完成」。已停止的 session 刪掉或改寫的問題，仍可在「更早、尚未回答的問題」中查看。按「結案」可結束單一問題。結案會一直有效，直到 agent 勾掉或刪除那個步驟、或工作改名；之後同樣的問題可以再出現在「等你處理」。時間從持久保存的首次觀察開始，不用心跳或匯入時間；未知或未來的觀察時間保守維持顯示。唯讀聊天與單次讀取使用既有基準，不建立基準。

備份或搬移時也請保留 `progress-questions-retired-*.json` 與 `progress-questions-consumed-*.json`。這些不可變紀錄只含版本、種類與不透明雜湊，避免舊檔案寫入讓已退役的識別或已遷移的隱藏標記復活。它們不隨時間或工作封存而刪除。紀錄無法讀取、不完整或無法寫入時，先停用隱藏直到儲存恢復；寧可多顯示問題，也不錯用舊標記。

側欄、終端和網頁以任務與 agent 辨識工作，不顯示連線清單或對話 ID；有支援的續接命令只在操作時複製。

問題排最前面，展開工作可看步驟。可勾選手動步驟、封存、貼入有效區塊、複製回覆或續接命令、標記已讀及還原。已讀只改本機隱藏清單，不傳話；實質不同的新問題會再出現。目前沒有通用任務編輯表單。

**確認完成**一次勾選所有未完成步驟，保留已取消步驟。即使尚無來源快取，後續 prompt 更新也保留這些取消項目；來源的新報告可取代該快照。可按側欄／網頁按鈕，或在終端選取工作後按 `d`。僅適用手動工作，以及已結束或超過 12 小時未寫入的 agent 區塊；工作已變動或仍在執行時會拒絕。每個新勾選都記入日誌；區塊會設為 `state=done` 並更新時間，再依原有等待期封存。不向 agent 傳話，`progress.html` 仍唯讀。

本機後續狀態更新會保留已完成步驟；新的明確工作回報仍可帶入新工作。

貼入進度保留來源時間。重複內容不變更；較舊或同時間衝突的進度會拒絕。無效或超前的時鐘須先修正；原有進度時間不明時，須比較兩份內容後確認取代。修復方式見[遠端回報](REMOTE_REPORTERS.md)。

卡片只有在確切 session 的 adapter 在線時提供傳送，否則複製或自行開啟 agent。[傳訊說明](MESSAGING.md)區分設定、真正回覆、重複、衝突及逾時。安裝不會任意接管已開啟的對話，一般回覆也不能批准工具、信任或 PR 合併。

`--no-open` 只印出網址，不開瀏覽器。關分頁不會停止本機服務，再執行同一 `--serve` 即可重開。**關閉看板**才會停止；若正在送訊，請等完成。預設不會閒置關閉，`--idle-minutes 30` 才啟用。舊版 `--allow-resume` 會明確啟用已結束 Codex／Grok 的重新啟動，預設關閉，也不會用作即時通訊的回退路徑。

#### 在手機上

網頁的版面適合手機。要從和電腦連同一個 Wi-Fi 的手機打開，跑 `node ~/.agent-board/agent-board.mjs --serve --lan`：除了電腦本機的網址，它還會印出網頁在你網路上的網址和它的 QR code，用手機相機對著掃就好。電腦有不只一個網路位址時，用 `--lan 192.168.1.23` 指定一個。Windows 可能會問要不要讓 Node.js 使用網路：在私人網路上允許，並確認 Windows 把你的 Wi-Fi 算成私人網路（剛連上的網路它會先當成公用網路），不然手機連不到網頁。跨網路存取須另行設定遠端連線。

網路上的網頁有這些限制：

- 只有加了 `--lan` 才開，只開在電腦的私人位址上（開頭是 192.168、10，或 172.16 到 172.31 的位址，絕不是公開位址），也只回應送到那個位址的請求。
- 它的網址帶著自己的一把鑰匙，不是電腦本機網頁那把。拿到這個網址或拍到 QR code 的人，在它關掉之前都能用這個網頁，所以只在信得過的網路上用，例如家裡的 Wi-Fi，不要在咖啡店的。
- 在網路上，網頁走的是沒有加密的 HTTP，同一個 Wi-Fi 上的其他裝置可能讀得到傳過去的內容，包括 agent 的回答。所以手機可以勾步驟、封存、標成已回覆（和重新顯示）、複製、貼上區塊和關閉看板，但不能回覆 agent：回覆會在電腦上跑一個程式，所以手機只顯示答案讓你複製，再從電腦本機的網頁送出。
- 10 分鐘沒有手機來看就會關，電腦本機的網頁關掉時也跟著關。開著的時候再跑一次 `--serve --lan`，拿到的是同一個網址。

開放前請讀[安全說明](../SECURITY.md)。

## 進度檔

`progress.md` 是儲存資料，不是 UI。每個 agent 擁有自己的區塊，不覆寫其他 session。格式支援英、繁中、簡中關鍵字，標記、所有權與寫入讀回規則見 [FORMAT](FORMAT.md)。

共用檔案不會自動跨機同步。[遠端回報](REMOTE_REPORTERS.md)是另行選用的流程。`dot` 標籤或貼上的區塊不能證明真正 dot 已連線。

## 選用 Claude Code 側欄

需要 Claude Code 2.1.287+；離線 CI 使用 2.1.301：

```sh
claude plugin marketplace add WenyuChiou/agent-board
claude plugin install agent-board@agent-board
```

開啟新 Claude Code session，使用 `/progress`。側欄鏡像 Task 工具，也可透過它的模型整理回合。問題與決策顯示於任務上方；側欄跟隨 Claude 主題，網頁跟隨系統主題，除非你在網頁上選了亮色或暗色。

`/agent-board` 會啟動（或沿用）可回覆問題、封存工作的看板網頁並提供連結，不動面板，每個工作階段都能用。Claude 桌面 App 的 Code 分頁沒有顯示面板時，底部狀態列會顯示等你的數量和「/agent-board 開啟看板」；那裡的 `/progress` 做同樣的事；互動網頁無法啟動時，兩者都開啟唯讀網頁。網頁啟動最多約需半分鐘，期間底部狀態列會顯示正在開啟。互動網頁需要由 `/progress connect` 安裝看板腳本，或在下次工作階段開始時更新。使用同一份已安裝的看板腳本的工作階段與 agent 會共用執行中的網頁。`/progress` 或 `/agent-board` 開的網頁在最後一個分頁關掉 30 分鐘後關閉，再執行一次該指令就有新連結；你自己用 `--serve` 開的網頁照它自己的設定。`/progress` 和 `/agent-board` 會換掉用 `--allow-resume` 開的網頁，除非那裡還有回覆正在送出；需要接續回覆時，之後再執行一次 `--serve --allow-resume`。Claude Code CLI 則顯示側欄。

| 指令／輸入 | 操作 |
| --- | --- |
| `/progress connect`、`connect status`、`connect remove` | 選用 plugin 連接、上次狀態、移除 |
| `+ 求職: 研究駐點 截止 11-20; 草稿; 送出` | 側欄快速新增，也可用 `/progress add …` |
| `/agent-board` | 啟動（或沿用）看板網頁並提供連結；不動面板 |
| `/progress open` | 產生並開啟唯讀 `progress.html` |
| `/progress tidy`、`/progress sync` | 封存符合條件工作；重讀 Task／PR |
| `/progress report`、`/progress today` | 複製週報／日報 |
| `/progress lang en`、`zh-TW`、`zh-CN`、`auto` | 側欄語言 |
| `/progress notify on`、`off` | 桌面通知 |

選用連接器需要 Node.js 18+；遷移前請重新載入較舊的 plugin 工作階段。原生 worker 跨資料目錄共用安裝鎖，持續記住移除停用意圖，並保留外部修改。側欄與輪詢先啟動，版本檢查在背景進行；缺少 Node 或設定記錄損壞時不修改設定。`connect status` 表示設定結果，不證明原生執行。

選用的 `scripts/setup.sh`／`scripts/setup.ps1` 處理 Claude 專用 Task 工具／profile 與 marketplace 設定。修改 profile 前先檢查範圍；獨立安裝不需要這些腳本。舊 plugin inbox 連接器可保留對話資料並呼叫 Claude 整理，和只記活動 metadata 的獨立 hooks 不同。[安全說明](../SECURITY.md)。

## 它怎麼保持整齊

已確認為程式啟動的 Codex 執行與 Claude 列印模式不會寫入新的看板區塊。看板腳本整理時，若舊 Codex 區塊自己的工作階段記錄確認它是程式執行，就移入封存，即使含有提問也一樣。記錄缺少或讀不到就不視為執行證據，仍依原有時間規則處理；選用側欄的整理不讀取歷程檔。弱提示維持原有行為。

選用側欄在 session 開始與每小時清理：完成區塊等 12 小時，其他已停／過時區塊等三天。持續執行的 `--serve` 網頁也每小時整理一次。手動工作每個步驟都是 `[x]` 或 `[-]`，且被觀察完成滿三天後，才計入可封存數量；0.24.1 的自動整理只計數，不移走任何手動工作。詳細資訊行會顯示「可封存 N 個已完成的任務」；數量為零時不顯示。工作中或等待中的 agent 區塊，最後寫入後 12 小時內仍算執行中；側欄、終端與網頁會說明暫不能封存，整理也會保留。停止或結束後，展開工作即可立即封存。 自動整理封存仍有 `[?]` 的區塊時，只有在保存並讀回與明確封存相同的完整問題快照後才會封存，而且要等夠久：已結束或已完成的區塊滿三天，仍在工作或等待中的區塊則是滿七天都沒有新報告；快照存不了就保留原處。問題會保留，列在「更早、尚未回答的問題」下，仍可隱藏與再顯示。明確封存任何時候都必須先有這份快照，來源移走後仍可找回；儲存失敗便保留來源。

執行 `node ~/.agent-board/agent-board.mjs --tidy` 可在沒有 Claude session 或網頁時，依正常等待時間整理一次；不會安裝排程，也不會寫入 `progress-seen.json`。側欄、`--watch` 或 `--serve` 會記錄手動工作首次被觀察完成的時間，以及三天規則首次執行的時間。三天從兩者較晚的時間起算，讓 0.24.0 就已完成的工作從升級後再等三天。電腦若只執行 `--tidy`，不會寫入啟用規則的保留紀錄，缺少這筆紀錄便不計數。未知、未來或讀不到的觀察時間都保留手動工作；`--tidy` 仍可封存時間已到的 agent 區塊。網頁的每小時整理若讀不到觀察檔，便跳過該次整理，不寫入任何檔案。

在側欄或網頁按「清理」（Clean up），會封存完成滿三天的手動工作，正好就是數量行計算的那些，再加上一般整理會移動的代理區塊。先寫入同一組每月封存檔，再從看板移走；未滿三天、未完成或有 `[?]` 步驟的工作會留下。若讀不到完成時間紀錄，清理不會封存任何項目，也不會寫入任何檔案，並會說明原因。0.24.1 的無人操作整理（側欄啟動與每小時、`--tidy`、網頁每小時）只計數，不移走手動工作。側欄的「現在封存」與 `/progress tidy`、網頁的「現在封存」，以及工作列的「封存」，仍可立即把完成工作移到每月封存檔，不會刪除工作。側欄與網頁在大小警告旁顯示一個「清理」按鈕，只要可封存數量大於零也會顯示，即使小看板沒有大小警告。數字及可封存數量放在詳細資訊行。終端看板、聊天和 `--html` 也顯示詳細資訊，但沒有按鈕。

超過 12 小時沒回報的卡片可能顯示已停，這是資料過時判斷，不是原生程序檢查；真正新事件／回報會刷新。超過七天沒動的工作折疊，不修改區塊；`--all` 或閒置開關可展開，快到期的工作保留顯示。已結束或過時的對話會移至獨立的已停止區，不再計入進行中；未回答的問題會離開「等你處理」，跟著工作留下，到期或閒置也一樣；已完成 session 的問題留在「最近完成」裡，移出後改到已停止區。在面板上按「結案」可結束單一問題；`--all` 或 `i` 可展開閒置和已停止工作。

側欄存下的紀錄（plugin 的 store 檔，在 Claude 設定資料夾的 `plugins/store` 底下）也有固定的大小。已結束 agent 的紀錄在最後寫入三天後清掉，session 存下的任務清單在七天後清掉，還有未完成步驟的留三十天；區塊還在看板上的紀錄一律不清。每筆紀錄都帶著它所屬看板路徑的短標記，所以看板只對自己的紀錄用較短的期限：同一台電腦上另一個看板的紀錄，要滿三十天才會被清掉（0.24 以前存的紀錄沒有標記，也是滿三十天才清）；看板自己在時鐘錯誤時寫下、日期比現在晚超過一天的紀錄，只要區塊不在看板上也會清掉。側欄標成 `.failed` 的收件匣檔案，從標記那一刻起留七天，不看檔案本身的日期。收件匣裡回報程式沒寫完就中斷、留下的 `.tmp` 暫存檔，滿一天就清掉；它是寫到一半的檔案，不是回合，所以不算進已清除的數量。清完仍超過 1.5 MB 時，會從沒在看板上、已結束的 session 紀錄由舊到新再清，直到低於上限；手寫的工作與等你回覆的步驟不會因大小規則被刪。其他 agent 的收件匣最多放 1,000 個檔案或 1.5 MB：寫入端丟掉最舊的，並把數量記在 `progress-inbox/dropped.log`。側欄與 `progress.html` 會用一行說明最近 7 天清掉了什麼，例如「最近 7 天清掉了 12 筆舊的 agent 紀錄和 340 則還沒讀的收件匣回合」，有清掉東西時才顯示。紀錄超過 1.2 MB（警告會說只有區塊已離開看板的 session 紀錄會被清掉）或 `progress.md` 超過 512 KB 時也會警告。

## 更新與移除

獨立安裝：將乾淨 checkout 更新到指定版本，預覽 `node scripts/setup-agent.mjs`，再套用已核准範圍。修改過的檔案列為衝突，不覆寫。host 可能要重新載入；不安裝自動更新器或開機服務。

用已安裝程式預覽／套用目標移除：

```sh
node ~/.agent-board/agent-board.mjs --codex-remove --agent <name>
node ~/.agent-board/agent-board.mjs --codex-remove --agent <name> --apply
```

`--codex-remove`、`--codex-doctor` 是沿用的維護名稱，可搭配各目標。先關閉該看板。只移除未修改的自有定義／檔案；其他目標還需要的共用檔案保留，進度、session 紀錄、封存、日誌及使用者修改也保留。

選用 plugin 請先在仍安裝時執行 `/progress connect remove`，完成回報的清理後，再執行 `claude plugin uninstall agent-board@agent-board`；marketplace 用 `claude plugin marketplace remove agent-board` 移除。更新用 `claude plugin marketplace update agent-board`、`claude plugin update agent-board@agent-board`，之後重新載入 plugin。

### 從舊名稱換過來

0.10 前的選用 plugin 名稱是 `project-progress@claude-progress-pane`。移除舊 plugin／marketplace，安裝上方新名稱；若使用其連接器，再於 Claude Code 內執行 `/progress connect`。保留原進度檔。獨立安裝不需要 Claude 遷移。

## 常見問題

### 可以只從一個 agent 開始嗎？

可以，使用共用安裝器從支援的任一 agent 開始，不需要另一家 AI。原生 hooks 依 host 而異；看板和明確回報自身進度的入口共用。

### 我是從 Codex（或其他 agent）裝的，它看得到 Claude Code 在做什麼嗎？

可以，只要各 session 回報到同一個本機進度檔。獨立 reporter 不需要 Claude Code 就能更新自己的區塊；選用側欄也讀同一檔案。開啟看板和接上原生收訊是兩件事。

### 換了一台電腦，東西都不見了嗎？

不會不見，但也不會自己搬過去：`progress.md`、收件匣和 hook 都只在各自的電腦上。在新電腦執行通用安裝器，再重開 agent 就好。要帶上以前的紀錄，就把你選用的 `progress.md` 和旁邊的 `progress-archive-*.md`、`progress-journal-*.md` 複製過去。

想讓兩台電腦共用一個面板，就在兩台都把 `CLAUDE_PROGRESS_FILE` 設成同步資料夾（OneDrive、Dropbox、iCloud）裡的同一個檔案，再在每台電腦各執行一次 `/progress connect`：自動連線只會跟著預設的進度檔，或你上次手動連線的那一個。一次只用一台最穩：兩台同時寫，同步軟體可能會留下衝突副本。

### 某個 agent 沒出現。

1. 執行 `node scripts/setup-agent.mjs` 預覽目前 host，查看衝突與 `adapter-pending`。
2. 依 host 要求重載，完成限定範圍的原生 hook 信任／啟用，再讀回確認。
3. 由該 session 使用自己的原生 id 回報，檢查精確區塊與更新時間；不要替其他 session 猜任務。
4. 另外觀察新的原生生命週期事件。進度出現不代表可以反向收訊，見[接線檢查](MESSAGING.md#connecting-a-session-that-was-already-open)。

選用 Claude 外掛另有 inbox 流程，該安裝可用 `/progress connect status` 查詢；獨立狀態 hooks 不需要 Claude 對話開著。

公開回報問題時，請提供：

- 看板、Node.js（`node --version`）與受影響 agent 的版本；使用選用 Claude 整合時才附該外掛版本。
- 作業系統、哪個 agent、做了什麼、預期結果和實際結果。
- 已移除私人資訊的安裝／doctor 輸出。

不要上傳原始收件匣、進度或對話紀錄檔。分享輸出或截圖前，移除提問、回覆、私人路徑、token（包括看板連結和 QR code），以及人名或專案名稱。請另寫一個小範例。`--chat` 只會盡力隱藏自身輸出中的家目錄路徑和常見憑證格式，無法保證完整，也不會清理診斷檔案。

虛構範例（填上版本，不需要真實對話）：

```text
作業系統：示範系統；看板／Node.js／agent 版本：<版本>
操作：在 demo-1 完成一個回合。預期：看板出現一列。實際：沒有出現。
安裝／doctor：<已檢查並移除私人資訊的狀態>
```

私人或涉及安全性的問題，請透過 GitHub 的 [Report a vulnerability](https://github.com/WenyuChiou/agent-board/security/advisories/new) 回報。詳見 [SECURITY.md](../SECURITY.md)（英文）。

### 會把資料傳出去嗎？要花多少錢？

獨立 reporter 只在本機保留挑選過的 session 中繼資料，不呼叫摘要模型。發訊給在線 agent會使用目標 agent 的模型與額度。下列模型與對話存取適用於選用的 Claude 外掛流程：看板檔案儲存在本機。透過你自己的 Claude Code 登入／模型存取，回合摘要會把提問和回覆傳給 Claude Haiku；標題會傳送該對話的第一個請求和步驟名稱；交接行會傳送最多 6,000 個字元的壓縮摘要。面板的側邊提問框也會透過同一個登入，把你的問題傳給模型，依這段對話的紀錄回答。這些呼叫使用該帳號的額度或計費。面板會執行 `git branch --show-current`，裝了 GitHub 的 `gh` 的話，也會用它查 pull request 和 CI 狀態。預設只傳給確切在線的對話；舊版 Codex／Grok 程序續接須明確加上 `--allow-resume`，使用該 agent 的權限與網路。獨立 OpenClaw 外掛停用對話存取；選用 Claude 連接器則設定 `allowConversationAccess: true`。

`--serve` 預設只監聽本機（`127.0.0.1`）；這台電腦上的任何程式只要有連結就能使用。`--serve --lan` 會透過帶 token 的 HTTP 連結，在私人網路分享網頁。token 是存取金鑰，不會加密：同一網路上任何拿到 LAN 連結的人都能讀看板、修改看板檔案（包括匯入區塊），也能停止伺服器。LAN 網頁會拒絕啟動 agent 的回覆，也不顯示恢復對話的指令。私人網路位址不代表咖啡廳或旅館的網路值得信任。不要分享連結或 QR code。要停止服務，請按網頁上的「關閉看板」按鈕；若正在傳送回覆，請等完成後重試。只關分頁，背景服務會繼續運作；閒置關閉須自行啟用。看板伺服器或 LAN 監聽器每次重新啟動都會產生新的 token，因此停止後舊連結就無法使用。檔案變更、啟動的程式、網路存取和 `--chat` 隱藏資訊的限制，詳見 [SECURITY.md](../SECURITY.md)（英文）。

### Windows 能用嗎？

本機看板支援 macOS、Linux、Windows；原生 hooks 與傳訊依 host 和介面分開驗收，見 README 的[支援的 agent](../README.zh-TW.md#支援的-agent)。獨立 Windows hooks 使用 Node，不需要 `sh`。

### 以前用的是 `claude-progress-pane`。

外掛在 0.10.0 改了名，不會自己換過去。照[從舊名稱換過來](#從舊名稱換過來)的步驟做就好，`progress.md` 不會動。

### 怎麼移除？

獨立安裝：先關閉看板，預覽 `node ~/.agent-board/agent-board.mjs --codex-remove --agent <name>`，確認後加上 `--apply`。進度與歷史會保留。選用 Claude 外掛的移除方式：

```sh
claude -p "/progress connect remove"
claude plugin uninstall agent-board@agent-board
claude plugin marketplace remove agent-board
```

第一行會把其他 agent 裡的 hook 拿掉；先處理完列出的清理問題，再移除外掛。歷史紀錄、回報腳本和收件匣會留著。重試方式、已經移除外掛時的補救步驟，以及保留檔案的位置，請看上面的[更新與移除](#更新與移除)。

## 疑難排解

- **沒卡片：** 檢查路徑、adapter、信任與重新載入；觀察真正事件並讀回確切 session 區塊，不手動製造事件宣稱通過。
- **不能傳送：** 確切原生 session 需要受支援的在線 adapter，hooks 本身不等於可收訊，桌面與 CLI 結果不可互代。
- **接線轉述被忽略：** 接收者應告知授權或阻擋原因；RPC 成功或 ACK 不等於已觀察到新進度。
- **讀寫失敗：** 處理指出的檔案／權限問題，檢查進度與歷史再重試；不先確認 owner 就刪鎖。
- **沒有原生側欄：** 非 Claude host 使用互動網頁或終端看板，網頁面板不等於原生側欄。
- **寫到一半被截斷的工作：** session 寫自己的區塊時如果中途停掉（當掉或被強制關閉），區塊可能少了結束標記。看板會把它讀成在它最後一行結束，照原樣顯示，並列在側欄最下方的「看板狀態」。要自己補上，就在它最後一行的下一行加上 `<!-- /auto session=<id> -->`；id 在區塊的開始標記裡。如果那個 session 先重寫了自己的區塊，新區塊下方留下的幾行會重複它舊的步驟：請自己刪掉。

### 安全地回報問題

提供 Agent Board／host 版本、CLI／App／IDE、OS 與合成重現資料；只有選用 plugin 才需要 Claude 版本。不上傳原始進度、inbox、封存、日誌、session log、憑證或看板 token。[安全回報](../SECURITY.md#reporting-a-problem)。

目前 Codex hooks 尚未在 /hooks 核准時，選用連接器會保留受管理的回報指示。Codex 確認核准後，connect 會拿掉這些指示，並記下這次核准對應的 hooks.json 與當時 Codex 的 config.toml。問不到 Codex 時（找不到執行檔、回應太慢、出錯、回答的格式這一版讀不懂），只要這兩個檔都沒變，就沿用記下的核准。Codex 回答 hooks 未核准、已關閉或不在清單上，或問不到 Codex 而其中一個檔改過時（任何改動都算，包括在 /hooks 取消核准或關閉 hooks，這會改寫 config.toml），connect 會把指示加回來。問不到 Codex、而找到的 Codex 執行檔不是記下核准時的那一個（例如 Codex 升級後）或讀不到時，也一樣會加回來。Windows 上用 npm 裝的 Codex，檢查時直接執行 npm 套件內的 Codex 執行檔，不經過 `codex.cmd`。status 查詢信任，但不修改指示。

完整來源也保存在看板旁、依內容定址的 progress-questions-source-*.json 檔案。備份或搬移時請保留整組 questions 檔案。側欄封存時（session 開始、每小時與側欄整理；看板腳本的 `--tidy` 不會）每種檔案（來源副本、retired 證明、consumed 證明）保留最新的 16 個，較舊的只有在 questions 檔或較新的副本已完整記下其內容時才會刪除；可能是唯一紀錄的檔案會留著，任何一個讀不到時就一個都不刪，一次整理最多刪 200 個，其餘留到下一次。同一次封存也只留最新的 3 個損壞的 questions 檔（questions 檔被截斷或寫壞時移到一旁的 `.torn-*` 副本），放超過一週的即使在最新 3 個之內也會刪除；寫到一半中斷留下的暫存副本放超過一天、且 questions 檔本身讀得出來時也會刪除。每次讀取都合併所有副本，過期索引無法刪掉原始來源。清理與明確封存前必須成功寫入並讀回完整副本。end 事件只關閉連線，不代表回答問題；同一來源的多個問題與僅出現在 end 的問題都保留。副本損壞或無法讀取時，拒絕清理來源與新的隱藏操作。
處理與解決後仍保留精確來源版本，因此重播舊的原始檔不會把已回答問題當作新問題；新的來源版本仍可被辨識。
明確封存會把完整未答副本保留在較早問題區；來源意外消失時仍沿用正常年齡政策，未知時間的問題維持顯示。
已結束、已完成或 12 小時沒有回報的 session，其未答問題仍留在該 session 的「已停止」列，同時會在「更早、尚未回答的問題」下列出一次，並顯示距離第一次提出已過多久（不會少於該 session 安靜的時間），以及專案、agent 與任務。「等你處理」底下只有一行「N 個未回答，在已停止的對話」，按下會打開這份清單；問題不會移進「等你處理」，等待數量也不會改變，即使同時出現在「已停止」列也只算一次。清單在面板、網頁與 progress.html 顯示前十個問題，其餘用「顯示全部（N）」展開；終端機看板則全部列出。在清單中，來源仍在檔案裡的問題，以及保留自已封存 session 的問題，可按「已回覆，先隱藏」；來源已消失、又不是來自已封存 session 的保留副本只供查看，不能隱藏。隱藏後的問題在面板與網頁列在「已回覆、隱藏的 N 項」底下，可按「重新顯示」；終端機看板只顯示這個數量，按 u 鍵全部重新顯示。目前還不能從看板回答保留自已封存 session 的問題，或把那個 session 找回來。這個版本之前已隱藏的問題維持隱藏、也不計入。
過期報告若仍使用相同的已知來源版本與問題文字，不會讓已解決問題重新出現。明確更新來源版本或實質改變問題文字後，問題仍可再次顯示。
終端、原生面板與網頁的提醒／較早問題區，仍有來源的問題可按「已回覆，先隱藏」，隱藏後的問題可在面板與網頁按「重新顯示」（終端機看板按 u 鍵全部重新顯示），不會變更來源或重設時間；保留自已封存 session 的問題也一樣。來源已消失、又不是來自已封存 session 的保留副本，在每個介面都會標明僅供查看，不提供隱藏按鈕。
原生面板的回覆若送出失敗或被拒絕，問題維持未讀。成功送出後仍會核對精確問題與來源；傳送期間重新提出的問題不會被標成已讀。既有問題移至保留區不會產生新通知。
