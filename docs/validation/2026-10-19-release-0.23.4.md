# Agent Board 0.23.4 release validation

This release packages the question-aging fixes from PR #139, tagged-board
adoption from PR #140 and Codex reporting fallback from PR #141. Questions remain
available after three and seven days; Mark read preserves their identity. A known
published board can upgrade without an old ownership record, while edited files
remain protected. Codex keeps its managed reporting instructions until the exact
enabled hook definitions are confirmed trusted.

The integration includes main `9d1a64645d1c9a4806e8bb809b0281a3ee6af083` and
PR #141 head `c6085c169dc5dd89c5b313aff15d3ace13c402ea`. Before release metadata:

- All six exact-head CI jobs passed: Linux and Windows each passed 517 plugin
  tests with Claude Code 2.1.301; Node 22/24 checks passed on both systems.
- The complete local 11-file Node 24.12.0 suite passed 263 tests, failed none and
  skipped two platform cases in 451.631 seconds. All 95 input hashes remained
  unchanged. The command used `--test-timeout=60000 --test-concurrency=1`.
- Supported standalone strict TypeScript, strict plugin validation and the pinned
  Bun checks passed on that runtime. Full `tsc -p .` remains unrun because the
  host-generated SDK is unavailable.

Earlier failures, fixture corrections and limitations remain in
[Codex fallback validation](2026-10-19-codex-fallback.md) and
[tagged-board adoption validation](2026-10-19-tagged-board-adoption.md).

The three README changes are version badges only; original images and layout
remain intact. Build outputs use Bun 1.4.2 and are generated by the release
procedure in CONTRIBUTING.md. Final release acceptance requires both generated
checks, ownership regressions and the release PR's six exact-head CI jobs.

The release procedure completed two generated-table passes around the bundle
build. Both final `--check` commands passed together with Bun 1.4.2. The new
452754-character bundle then passed all five ownership regressions (current
fingerprint exclusion and four actual tagged-adoption cases) in 3.256 seconds on
Node 24.12.0. Strict plugin validation and whitespace validation also passed.

These checks invoke no model and change no installed host settings or trust.
OpenCode native messaging is not accepted by this release: its bounded request
received a provider APIError/403 without an ACK, and further requests were skipped.
Native receiving, automatic activity and explicit task reporting remain distinct
capabilities; a progress card alone proves none of the other two.
