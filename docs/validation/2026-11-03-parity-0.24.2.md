# Live parity record — Agent Board 0.24.2, 2026-11-03

A full pass of `PARITY-CHECKLIST.md` on Windows 11 for #841, run together with the live real-agent round of #609. It ran on the owner's PC with the owner at the computer. Every prompt was synthetic and ran in a scratch project folder that holds two test files.

**The commit the rows ran on:** `agent-board--v0.24.2` (4a9785f), the release published to npm as `next` 0.24.2. No row ran on another head.

**Hooks and the version they run.**
- **Real home.** The Claude Code plugin installed there is 0.24.2, read from its `plugin.json`. That evening it wrote the board script and the reporter:
  - the board script holds the version string 0.24.2, and the page footer reads `v0.24.2`;
  - the Codex and Hermes hooks call that reporter.
  - Nothing was set up, connected or removed in the real home.
- **Isolated homes.** Claude Code CLI ran with the tag's plugin through `--plugin-dir`, in an isolated home. #609 step 1 used a second new home. In both, every variable in the checklist's isolation list pointed into the folder.

**Boards.**
- Checks c, d and f used a synthetic board through `CLAUDE_PROGRESS_FILE`, with its own `--serve` page and terminal board.
- Check b and #609 steps 3 to 6 were read on the owner's real board. The hooks always write into the real home's inbox. A watcher noted, by file name and time only, which inbox files named the scratch folder.

**Rules this run could not follow.** The run started before the checklist changes in #847 (e00fc73) and #850 (1b74a6c) were merged:
- **The kept test home.** There was no kept test home yet. Each isolated home was new, so the one-time steps came back:
  - the owner signed in to Claude Code in the isolated home;
  - the owner answered the Hermes hook prompt (`Allow this hook to run? [y/N]`) with y;
  - the owner pressed the Codex app's trust prompt for the scratch folder.
  - The isolated homes are kept on the runner's PC as they are, not removed.
- **Asking the owner.** The owner was asked during the run as each screen came up, not in one list before and one after. The list of screens still waiting for the owner went to the owner in chat, in Chinese, at the end of the run.
- **Prompts pressed by the checker.** None. Every sign-in, trust, consent and hook prompt in this run was pressed by the owner.

**How the CLIs were run.** Each CLI turn ran in its own console window in print mode, so the hooks fired as usual: `codex exec`, `hermes chat -Q -q`, `agy -p`, `cursor-agent -p`, `opencode run`, `grok -p` and `gemini -p`. Claude Code CLI ran interactively, because the plugin sums up a turn only after the reply. So did one Codex CLI session, for the delivery test (see "Codex direct delivery"). Every CLI that ran has at least one window screenshot.

## Codex direct delivery

The owner's main question for this run: can the board deliver an answer to a running Codex session?

**What was run.**
- An interactive Codex CLI session was started in the scratch folder, on a synthetic turn that runs `Start-Sleep -Seconds 240` and then asks "Blue or green?". Opening it started Codex's managed app-server daemon.
- While the turn ran, the shipped connector `scripts/codex-message-connector.mjs` got the explicit binding on stdin that MESSAGING.md asks for: the page, the absolute Codex executable, the thread and its active turn.

**Result: not delivered.**
- The connector exited 1 after 5 s with `{"error":"OWNER_TIMEOUT"}`.
- `codex app-server proxy` sent no line in reply to `initialize`. The same silence came from:
  - the CLI's own binary;
  - the CLI with `--sock` set to the daemon's control socket;
  - the daemon's 0.165.0 binary.
- So nothing was attached, and the card offered no Send.

**What the person saw.**
- The card showed `Copy "Blue"`, `Copy "green"` and `Write your own`. Pressing `Copy "Blue"` showed `Working…` for about 2 s, then "✓ Copied to clipboard" and `Copy again`.
- The card showed no Accepted, received or delivered state, and the answer never reached the Codex turn.
- The card stays in Needs you, with no hide button, until the person answers in Codex.

The details are on #557, which tracks this for 0.24.3.
