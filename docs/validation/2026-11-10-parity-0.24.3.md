# Live parity record — Agent Board 0.24.3, 2026-11-10

A pass of `PARITY-CHECKLIST.md` on Windows 11 for the release pull request #1266. Every prompt was synthetic and ran in a scratch project folder of the kept test home. This record holds the CLI rows and the shared board rows run by a Claude Code subagent (Claude Sonnet), with the maintainer's check of the findings. The app and IDE rows were not run for this pre-release (see "Apps and IDEs").

**The commit the rows ran on:** `0bf544022fc991a18fb814cab55e3d28516d8267` (release pull request #1266 head, checked out and read-only). No row ran on another head.

**Not re-run on the release head.** After these rows, the release took two fixes from `main`: #1248 (how the board finds the question a reply ends on) and #1264 (saving settings). Both change shipped files, so under [PARITY-CHECKLIST.md](PARITY-CHECKLIST.md) these rows do not cover the final head. 0.24.3 ships as a pre-release, whose gate needs only the simulated-user run, and that ran again on the final head. A full parity run on the head to promote, with the app and IDE rows, comes before 0.24.3 or a later version is marked stable.

**Where it ran.** Every row ran in the kept test home, which stays on the runner's computer and is not named here. Before the first row the release was installed in it:
- `setup-agent.mjs` preview, then the same with the ten agents it listed and `--apply` (Codex, Cursor, OpenCode, Gemini, Grok, Muse, Hermes, OpenClaw, Antigravity, DeepSeek). A second preview afterwards listed every agent as already set up.

The marketplace of that name pointed at an older checkout, so it was replaced. `claude plugin list` then read: agent-board 0.24.3, read from the release checkout.

**How the CLIs were run, and what that means.**
- `claude -p`, `codex exec`, `cursor-agent -p` and `opencode run` are runs a program starts. 0.24.3 hides them from the board's rows on purpose (`origin: run`), so a card for check b needs an interactive session. Claude Code, Codex, Cursor and OpenCode were therefore started interactively in the Terminal panel with the first prompt on the command line. Hermes, Grok, `agy` (stream-json, no tools) and OpenClaw (`--local`) produced a card in headless mode.
- The Terminal panel only takes a command line, so no second prompt could be typed into an interactive session. That is why "next turn" delivery to Codex could not be observed (see "Live delivery").
- **Screenshots.** 0 pictures. None of the CLI windows was saved as a picture: the screenshot tools here capture the whole desktop (with other sessions and an account name on it) and cannot crop to one window. In their place the maintainer keeps about 20 masked terminal transcripts of the CLI runs, off GitHub. The terminal screens of the four interactive sessions were read through the Terminal tool and are summarised in the rows, not saved.
