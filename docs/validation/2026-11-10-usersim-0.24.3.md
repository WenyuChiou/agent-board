New steps this run: #1292 (`--serve --port 65536`), the SSH line (#1283/#1293), and the real Claude Code with this head's plugin.
  - P1 ran with `LANG=en_US.UTF-8` (this computer is zh-TW); P3 zh-TW with no `LANG`; P3 zh-CN with `--lang zh-CN` on setup.

The real Claude Code was started once with this head's plugin (`claude --plugin-dir <release checkout> -p hello`); it stopped at `Not logged in`. No agent was signed in, so every session is synthetic: the installed Codex hook command ran with a hook event on stdin; the Claude Code, Antigravity, Cursor and OpenCode rows and the hand-kept task are blocks written in the file's format.
  - Without a terminal to answer in, setup only previews, so `Set these up? [Y/n]`, `--watch` and the terminal keys were not seen on Windows. An interactive SSH terminal was not available either: the SSH step ran as a non-interactive call with `SSH_CONNECTION` set.

- **Linux (P2).** The third run's scripts, pointed at the new package and a new empty home `<home>` in a temporary folder, with every home and agent variable pointed into it, `CLAUDE_PROGRESS_FILE` unset, and a PATH with no Windows folder. The home held synthetic user settings for Codex, Claude, Cursor, OpenCode and Antigravity. No agent is installed in WSL: sessions are synthetic (the installed hook command with a hook event on stdin, the agent's `--report` command, or a hand-written block), and a Codex trust step cannot succeed without Codex.   - The bare command over SSH was a simulated session in a real pseudo-terminal: SSH_CONNECTION and SSH_TTY set, DISPLAY and WAYLAND_DISPLAY unset. No SSH server is installed in WSL. It was run once with no agent override variable (what a P2 user has), then with `HERMES_HOME` and with `OPENCODE_CONFIG_DIR` set to a folder in the home.
